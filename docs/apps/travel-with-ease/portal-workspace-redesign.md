# TWE portal workspace redesign — phase 1
Approved direction: Faako workspace shell + modular operations studio. This PR changes only the shell, navigation, page heading and typography foundation, not CMS data or publication workflows.

- The desktop sidebar uses shared ErpNavSidebar and shared collapse persistence with a backward-compatible controlled navigation adapter. The existing guarded navigate function remains authoritative for dirty drafts and role-filtered destinations. Only the active module reveals permitted contextual destinations; Account remains in the footer. Mobile retains the proven drawer and five-shortcut navigation (900px breakpoint aligned with Faako).
- Neutral grey shell, white workspace, navy accents and consistent radius tokens; no new icon library. Use shared Iconsax and shared topbar.
- Public website's approved typography from its typography.css: Poiret One (400 with optical stroke), Quicksand body, Inter accents/navigation. Use compact portal sizes, no decorative signature headings; website preview keeps its own typography. Actual files are Fontsource WOFF2 with Latin and Latin Extended subsets and OFL notices, pinned to an inspected upstream Git commit. Vite downloads and verifies these public assets only if the local cache is absent or invalid. Browser font loads remain same-origin; no portal CSP or authentication changes. A fresh build needs network access to raw.githubusercontent.com; a cached build doesn't.
- Existing API contracts, permission checks, session preservation, autosave, publication, role restrictions and 02:00 UTC app update schedule remain unchanged.

Acceptance: shared navigation desktop, collapse/expand and context visibility, permission filtering, mobile keyboard and touch navigation, dirty draft guard, real font loading, viewport overflow, independent staging smoke test. Remaining phases: dashboard and enquiry UX, structured content editor, media and synchronisation, communications/form builders, administration, complete rendered QA.

## Phase 2 — operational dashboard and enquiry inbox
- Independent dashboard resources for summary, recent records, drafts and publication jobs. A failed request no longer masks other data or reports false zero counts. Manual refresh retries each resource. Publication activity uses actual returned jobs; no invented trends.
- Enquiry list and selected detail fetch independently; preserve filters and pagination on selection. Wide workspace uses master-detail view, smaller screens retain full-width detail and restore focus on return. Existing version checks, CSRF, permission checks, snapshot rendering and status-only writes remain intact.
- Browser regression coverage includes partial dashboard failure; final live visual acceptance remains outstanding.

## Phase 3 — website editing workspace
- Current section heading replaces the duplicate Website content heading. Section picker remains available in both editor and preview modes; a guarded draft-list shortcut and current-page outline jump to copy, imagery, SEO, publication and revision history.
- Sticky save/preview/publication command bar uses the existing form submit, autosave and publication handlers; no duplicate publish button or changed publication scope. The publication shortcut focuses the existing scope and confirmation panel. Existing private viewport preview now supports full-width preview as well as desktop split view.
- Expandable editorial groups start open, retain their existing fieldsets and validation; invalid fields open their containing disclosure. SEO receives its own group. Read-only and publication-busy controls are tightened. Technical image geometry remains Superadmin-only.
- Browser acceptance now checks sticky commands, outline focus and disclosure interactions. No new API endpoints or provider config; publication and restore remain unchanged. Rendered staging review still required.

## Phase 4a — media workspace and record interactions
- Full-surface native buttons for Drive folders, image selection, library asset preview/use, and dashboard draft rows. Secondary mutations stay separate and behind accessible disclosures, avoiding nested interactive controls.
- Library search and grid/list presentation; mobile defaults to compact thumbnail rows. Drive browsing uses the approved folder tree, loaded-page search and per-revision import state, with existing required alternative text and immutable import endpoint. Images in the private library use existing authenticated preview URLs; raw Drive files are not fetched in the browser. Existing upload, replace, archive, CSRF and confirmation semantics remain.
- Mobile design rule: show essential record data first, reveal the remainder on demand. Do not hide business actions solely by screen size. Apply full-row/card actions throughout subsequent modules and final acceptance. Automatic background Drive sync, server-side Drive thumbnails and multi-file import are not part of this commit; those require separate reviewed backend behavior.

## Phase 4B — opt-in automatic Drive–R2 sync
- Existing API hosts the bounded scheduler, no new service or provider credentials. Enabled only with TWE_DRIVE_SYNC_ENABLED=true and configured Drive/R2 on a deployed environment. Starts after one minute, progresses by page and up to three imports per minute, waits one hour after a completed/failed scan. Traversal progress is in memory and restarts safely after deployment. PostgreSQL advisory lock limits simultaneous scheduler work; immutable revision uniqueness handles concurrent staff imports.
- Only new, unarchived revisions with a nonempty Drive Description of at most 500 characters are imported automatically as the image's alternative text. Missing descriptions are shown for manual review. Revalidates metadata/ancestry/checksum and uses the same private image processing pipeline. No deletion, overwrite or publication. System action is recorded as media.drive_synced with a null staff creator (migration 022); existing actor references retained. Status is local to the serving API process, not a persistent global job ledger.
- Activation requires staging verification of OAuth, approved folder descriptions, migration, and R2 writes; no live variable or resource changes in this PR. Tests cover recursive scanning, paging, throttling, incomplete listings and deduplication behavior.
